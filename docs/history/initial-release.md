## 入力素材と移植

ユーザー提供 `hikari-no-oekaki.zip`（9,507,772 bytes）から移植しました。取得元コミットは `06923931d29a892c4e76c093eef76a4ca53d4bfd`、SHA-256 は `0be91a73a807a55637cc3a46c324f1c0ddbb23ea7e44c1a77c4587515d9f7efe`。Library の元ZIPは `libfile_d1e65fe5fe208191812e00599bd8caff` です。

4枚の葉はユーザー提供の透過画像で、各1254×1254 RGBA。個別Library IDは `library-provenance.json`、MP3のIDは `audio-provenance.json` に保持しています。MP3は47,953 bytesで変更なし。元資料にない作者・ライセンスは推定していません。

最大表示330 CSS px・DPR上限2に合わせ、660×660の配信用派生画像を比較しました。原本は上書きしていません。

| 4枚合計                           |     bytes | 元からの削減率 |
| --------------------------------- | --------: | -------------: |
| 原本PNG 1254px                    | 4,803,460 |              — |
| 縮小・最適化PNG 660px             | 1,415,195 |          70.5% |
| 透過可逆WebP 660px                |   970,988 |          79.8% |
| 採用: 透過WebP quality 88 / 660px |   316,354 |          93.4% |

4枚の実画像、330px表示の原本／縮小PNG／採用WebP比較、ブラウザの背景を目視確認しました。葉の水彩調の質感と透過境界を保ちつつ転送量が小さいWebPを採用しました。アプリ参照と開発・テストサーバーの `image/webp` MIMEを更新しています。

再生成には Pillow が必要です（アプリ実行には不要）。`python3 scripts/optimize-assets.py` で生成できます。Pillow/WebPの版により圧縮バイト数は変わり得ます。比較画像は `test-results/asset-comparison/comparison.png`、個別容量は `optimization.json` に出力します。

## 初期検証

2026-10-20、クラウドLinux / Node.js 24 / Chromiumで検証。`test-results/results.txt` が実行結果です。

- ビルド、WebP4枚の660pxデコード、MP3の配信バイト一致とデコード。
- iPhone相当390×844／844×390、iPad相当820×1180／1180×820、1280×800。描画・タップ・長押し・多指・cancel・画面サイズ変更。
- 花の寸法・重なり順のピクセル検査、最大10指、2,000タップ、5,000移動、効果終了後の描画停止。
- 音の有効化、消音、復帰、音声上限、読込遅延・HTTP503時の描画継続、非表示・pagehide/pageshow。
- 入口320／390／1180px、カード1本、横溢れなし、56px操作、リセット、消音、戻る・再入場を計9回。

元テストの短タップ比較ではリモートブラウザへの通信時間が花径に加算されるため、0秒の比較ジェスチャーを同一ブラウザ評価内で終了するように修正しました。実際のタップや長押しの検証も別途残しています。

実機iPad/iPhone Safari、実機の同時多指、OSジェスチャー、実際のバックグラウンド復帰、音色と音量の聴感は未確認です。エミュレーションは実機検証の代わりにはなりません。
