# おもちゃボックス

幼児向けの小さな遊びの入口と、「ひかりのおえかき」1本の初期版です。ビルド結果は静的ファイルのみ。ログイン、投稿、サーバー保存、アクセス解析、外部CDNはありません。

## デザイン方針

入口と今後追加するすべての遊びは、幼児の見分けやすさ・操作のわかりやすさを優先します。

- 鮮やかな色、はっきりした形、十分なコントラストを使い、洗練された雰囲気や淡い配色のために視認性を下げません。
- 操作対象は大きく（56 CSS px以上）、間隔を確保します。絵や形で案内し、文字や色だけに頼りません。
- 触る・なぞるなどの操作直後に、大きく弾む・広がる・動くなど、結果がはっきりわかるにぎやかな演出を優先します。動き・形・粒子などで楽しく派手にし、強い連続点滅や突然の大音量に頼りません。
- 過度な点滅・刺激や大きすぎる音を避け、消音と動きを減らす設定に配慮します。

素材表現をコード生成だけで済ませず、画像生成や必要に応じた3D素材制作を積極的に活用します。具体的に画像生成が必要な場面では、用途・仕様を整理してクルミさんと協力します。幼児向けの鮮やかさ・わかりやすさを優先し、画像は表示に適した解像度・透過・WebP等の圧縮、3Dはポリゴン数・テクスチャ・描画負荷の調整をセットで行い、Webで軽快に動く素材にします。

既存の「ひかりのおえかき」の見た目の調整は別途行います。この方針の追記自体では再デザインしません。

## 実行

Node.js 22以降（検証は24）を使用します。npmパッケージのインストールは不要です。

```sh
npm run build
npm run dev
# http://127.0.0.1:4173
```

`src/` を編集し、変更後に `npm run build` を実行します。`dist/` が配信対象です。`file://` ではモジュールや音素材の取得制約があるため、HTTPで開いてください。

```sh
npm test
# 必要な場合: CHROME_PATH=/path/to/chromium npm test
```

テストは専用一時プロファイル・自動選択ポートのHTTPサーバーを使い、終了時に停止します。クラウドLinuxの `/usr/bin/chromium` が既定です。クラウドのヘッドレス検証では `--no-sandbox` を指定するため、テスト対象はこのローカルコードだけにしてください。ブラウザ内の状態フックはテスト時のみ注入し、配信ソースには含めません。

## 構成と追加方法

- `src/index.html`, `box.css`, `box.js`: 遊びを選ぶ入口。
- `src/games.js`: 遊びのタイトル・説明・リンクの一覧。
- `src/games/hikari-no-oekaki/`: 独立したHTML/CSS/Canvas JSと配信用素材。
- `source-assets/hikari-no-oekaki/`: 葉画像の原本、出典情報、元README、最適化記録。
- `scripts/`: 静的ビルド、ローカル配信、画像変換。
- `tests/browser.mjs`: 元の遊びの回帰テストと入口・往復の検証。

遊びを増やす際は `src/games/<slug>/index.html` と必要なファイルを追加し、`src/games.js` に1項目追加します。入口のカード図案は現在ひかり用なので、別の遊びには図案の識別子と表示分岐も追加してください。ゲーム間でCanvasや音声状態を共有しないページ遷移方式です。各ページは `../../` への戻るリンク、56px以上の操作、終了・非表示時の音声と入力の後始末を備えてください。実装後は追加した遊び固有のテストと入口からの往復を確認します。

## 遊び方と今回の変更

カード全体で「ひかりのおえかき」を開きます。触れて離すと花、なぞると光の道、長押しすると6秒まで花が育ちます。元の花・線・粒・音・複数指の挙動と上限を維持しました。

左上に「もどる」、右上に「音あり／消音」、右下に「やりなおす」を配置しました。すべて56 CSS px以上で、セーフエリアを考慮します。リセットは描画・入力・発音を停止します。戻る操作は音を止めて入口へ戻り、再入場は新しい画面から開始します。音設定はページ内のみで、再入場時は「音あり」に戻ります。音は実際に触るまで再生しません。

## 素材の出典と最適化

ユーザー提供 `hikari-no-oekaki.zip`（9,507,772 bytes）から移植しました。取得元コミットは `06923931d29a892c4e76c093eef76a4ca53d4bfd`、SHA-256 は `0be91a73a807a55637cc3a46c324f1c0ddbb23ea7e44c1a77c4587515d9f7efe`。Library の元ZIPは `libfile_d1e65fe5fe208191812e00599bd8caff` です。

4枚の葉はユーザー提供の透過画像で、各1254×1254 RGBA。個別Library IDは `library-provenance.json`、MP3のIDは `audio-provenance.json` に保持しています。MP3は47,953 bytesで変更なし。元資料にない作者・ライセンスは推定していません。

最大表示330 CSS px・DPR上限2に合わせ、660×660の配信用派生画像を比較しました。原本は上書きしていません。

| 4枚合計 | bytes | 元からの削減率 |
| --- | ---: | ---: |
| 原本PNG 1254px | 4,803,460 | — |
| 縮小・最適化PNG 660px | 1,415,195 | 70.5% |
| 透過可逆WebP 660px | 970,988 | 79.8% |

4枚の実画像、330px表示の原本／縮小PNG／採用WebP比較、ブラウザの背景を目視確認しました。葉の水彩調の質感と透過境界を保ちつつ転送量が小さいWebPを採用しました。アプリ参照と開発・テストサーバーの `image/webp` MIMEを更新しています。

再生成には Pillow が必要です（アプリ実行には不要）。`python3 scripts/optimize-assets.py` で生成できます。Pillow/WebPの版により圧縮バイト数は変わり得ます。比較画像は `test-results/asset-comparison/comparison.png`、個別容量は `optimization.json` に出力します。
