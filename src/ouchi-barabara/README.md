# おうちバラバラ

画面をタップすると黄色いショベルカーが自動で動き、バケットでおもちゃの家を叩いて崩します。three.js で描画し、cannon-es の簡易な剛体物理で破片を落とします。得点・失敗・時間制限・文字の案内はありません。

現在は初期仕様の Phase 2 までを実装しています。長押しでの連続攻撃、全壊後の瓦礫遊び、「次のおうち」アイコンでの入れ替えに対応しています。建物は2階建て1種類で、配色だけを毎回変えます。ほかの建物（Phase 3）と効果音は未実装で、効果音は Phase 3 のあとに別途追加する予定です。

## 設計上の判断

- 建物は [house-plan.ts](house-plan.ts) に、大きな部品と攻撃ごとの破壊エリア・ショベルカー位置・バケット目標をデータで定義します。実行時のメッシュ切断や構造解析はしません。立っている部品は質量0の静的物体です。cannon-es では質量を持つ静的物体が衝突計算で動く物体として扱われるため、壊れた瞬間に質量を与えて動かします。
- アームは [rig.ts](rig.ts) の2関節の逆運動学で、打撃の瞬間に歯先が目標へ一致します。目標は必ずその攻撃で壊れる部品の表面に置き、空振りに見えないようにします。前進は前方向だけで、キャタピラは建物の正面より手前で止めます。
- 物理演算は大きな部品だけに限ります。小さな破片と砂ぼこりは物理なしの演出用で、上限のあるプールで再利用します。止まった部品は休止させ、どうしても静止しない部品は一定時間で強制的に休止させます。
- 破片はショベルカー側へ飛ばしません。前側の屋根はショベルカー側へ下る斜面なので、家の内側へ落とします。ショベルカーとバケットには運動学的な物体を持たせ、瓦礫をすり抜けずに押します。バケットが瓦礫に触れるのは振り下ろしの間だけです。振りかぶりや戻りでも触れると、瓦礫をすくってショベルカーの上へ運んでしまいます。バケットが押す速さには上限があり、破片が画面外へ飛ばないようにしています。
- 物理の正確さより「わかりやすく崩れること」を優先し、次の調整をしています。
  - 2階の床は前後・左右に4分割し、打撃点の継ぎ目から V 字に折れて落ちます。1枚の重い板のままだと、平らに落ちて衝撃を受け止めたように見えるためです。床は下の壁より少し遅れて崩します。
  - 攻撃ごとに威力（`power`）を指定できます。地面に立つ1階の壁を崩す攻撃は、威力を強めています。
  - 崩れた壁には、短時間だけ外向きの速度を保つ「押し出し」を物理演算の外から加えます。上に載った床や接触摩擦があっても、確実に倒すためです。
  - 打撃の瞬間に、近くの既存の瓦礫も弾きます。部品を崩すときは、休止中の瓦礫をすべて起こします。cannon-es は休止中の物体を動かない壁として計算するため、起こさないと新しく崩れた部品が止められてしまいます。
  - cannon-es の摩擦は、荷重に関係なく接点ごとに一定の大きさで働きます。そのため、摩擦係数は現実の値より低くしています。部品の当たり判定も水平方向だけわずかに細くして、横に隣り合うブロック同士が触れないようにしています。
- 画面全体がタップの対象です。攻撃中のタップは少数だけ予約し（上限は app.ts の `MAX_QUEUE`）、それ以上は捨てます。指を押し続けると、攻撃を1回ずつ続けます。離した時点で動いている攻撃は、最後まで再生します。
- 全壊後のタップは瓦礫遊びになります。手の届く範囲で、タップしたおおよその方向にある大きな破片を選びます。そのなかでなるべく同じ破片が続かないようにして、叩いて跳ね飛ばします。同じ場所を続けてタップしても、狙う破片は変わります。ショベルカーはその場から動きません。
- 「次のおうち」は、新しい家が急に現れるのではなく、前へ進んだ先にある形で見せます。バケットを地面近くまで下ろして瓦礫の中を前進し、瓦礫は左右へ押しのけます。前方に押すと次の作業場に溜まるので、物理演算の外から横向きの力も加えています。次の家は、前進を始める時点で1区画先に建てます。区画の間隔（[scenery.ts](scenery.ts) の `SITE_SPACING`）は、縦長の画面で道の先まで見えても建てた瞬間が映らない長さにしています（`ouchi-model` テストで検査）。長い道は、一定の速さで進む区間を挟んで移動します。前の作業場を通り過ぎたら、ショベルカーは瓦礫に触れなくなります。引っかかった破片を道の先まで引きずらないためです。
- 道沿いの景色（[scenery.ts](scenery.ts)）は、作業場の間隔ごとに同じ配置を繰り返します。到着したら、ショベルカー・家・カメラを1区画ぶん戻し、座標が増え続けないようにしています。景色は繰り返しなので、戻しても見た目は変わりません。前の家の瓦礫は、到着の時点で物理演算から外し、縮めて消します。
- カメラ（[camera-rig.ts](camera-rig.ts)）の構図は、縦横比に応じて作業場全体が収まるように決めます。縦長の画面ではショベルカーの後ろ寄りから見て、奥行き方向に並べます。次の家へ進むときは、臨界減衰のバネ（ゲームエンジンで一般的な SmoothDamp）でショベルカーを少し遅れて追い、進行方向の少し先を映します。ショベルカーが画面の中で固定されず、動いて見えるようにするためです。
- 描画ループは、動き・物理・演出がすべて止まると停止します。ページの非表示・離脱では停止して予約を捨て、復帰しても勝手には再開しません。バックフォワードキャッシュから戻ったときは、新しい家から始めます。
- 動きを減らす設定では、カメラの揺れと砂ぼこりを省き、破片の勢いを弱めます。次の家への移動も短くし、カメラは遅れずにすぐ追従し、先を映すずらしもしません。建物が崩れる結果と、次の家に着いたことはそのまま見えます。
- 影を計算する範囲は、画面に映る地面全体から求めます。縦長の画面は道の先まで映るので、範囲が広いときだけ影の解像度を上げます。
- 「次のおうち」ボタンは、最後の崩壊が終わったときに一度だけ現れ、次の家へ進むまで出たままにします。瓦礫遊びの最中に出入りして、登場の演出が繰り返されないようにするためです。
- WebGL を使えない環境では、絵文字と短い文で遊べないことを伝えます。

## 検証

`node --import tsx tests/ouchi-model.mjs` で、全攻撃の到達可能性・歯先の一致・破壊エリアの割り当て・前進方向を検査します。`node tests/ouchi.mjs` はヘッドレス Chromium（SwiftShader）で、3つの画面サイズでのタップ・予約上限・4回での全壊・瓦礫遊び・ループ停止を検査します。さらに、長押しの連続攻撃、次の家への移動と座標の戻し、移動後の打撃位置、キーボード操作、非表示時の停止、再入場、動きを減らす設定も検査します。描画の滑らかさは実機での確認が別途必要です。

ショベルカーと家は、本プロジェクトで形状を設計してコードで生成しています。外部の3D素材は含みません。ショベルカーは押し出した輪郭を部品ごとに材質単位でまとめ、描画回数を抑えています。当たり判定は車体とバケットの箱2つだけで、見た目の細かさと物理演算の負荷は無関係です。
