# おうちバラバラ・聴き比べ候補

音源IDと固定記号は [review.json](../../../../src/ouchi-barabara/sound-review/review.json)、対応するファイルとSHA-256は [candidate-identities.json](candidate-identities.json) に保持します。以下の生成記録は初回A・B・Cのもので、追加候補はD以降へ追記します。採用状態を変えても記号とファイルの対応を変えません。

| 場面 | Bの生成意図 | Cの生成意図 |
| --- | --- | --- |
| hit | 低く空洞に響く木のおもちゃ | 弾むプラスチックのおもちゃ |
| collapse | まとまって倒れる木の積み木 | 軽いプラスチックのブロックの崩れ |
| rubble | 小さな木片の軽い転がり | 小さなブロックの短い跳ね返り |
| drive | 低めでやわらかい玩具モーター | 軽い歯車・キャタピラの機械音 |

原本WAVは生成記録の `originals_directory` が示すGit管理外の保管先、モデル・版・プロンプト・seed・生成条件は [generation.json](generation.json) に保持します。採用判断と音色の試聴は人が行います。モデルと利用条件は [既存音源の利用条件](../README.md#利用条件) と同じで、新しい外部録音素材・ライセンスは追加していません。

[prepare.py](../prepare.py) に `--review` を渡すと、新候補だけを加工します。現在の音のデコード後RMSに近づけてレベルを調整し、短さ・前後のフェード・帯域・ピークを整えます。聴感上の音量の一致を保証する処理ではありません。音源別の加工条件・元ファイルと出力のSHA-256・デコード後の測定値は [optimization.json](optimization.json)、出力先は `src/ouchi-barabara/sound-review/assets/` です。比較画面でもゲームと同じマスターゲイン・再生時の短いフェードを使います。

選定結果はブラウザー内の下書きまたは書き出したJSONで保持します。このフォルダーの生成記録は選定状態を示しません。JSONの候補セットID・場面・候補ID・メモ・単音／ゲーム内の確認状態を読み、採用したファイルを通常の配信用素材へ反映するときに既存の素材記録も更新します。選定を人が行う前に確認済みとは記録しません。

候補の音を変更するときは次の記号を追加し、元の音源とIDを保持します。候補の追記では `CATALOG` を変えず、既存の選定結果を同じ音源へ読み戻せるようにします。候補一覧に上限の記号を設けず、Zの次はAA以降を使います。

## 固定記号と追加候補

[初回の選定結果](selections/2026-11-11-v1.json) に基づき、打撃Aを維持し、走行Cを採用しました。初回の確認状態を、変更後の音の組み合わせの確認済みとしては流用しません。初回Aの走行・崩壊音も比較素材として保持します。

初回のA・B・Cをそのまま固定し、崩壊・瓦礫の調整音はD・Eとして追加します。走行の採用音はCのままです。初回Aは通常配信ファイルから独立した `*-original.mp3` に保持し、採用音の変更で別の波形に差し替わらないようにします。現在の全候補は上記の台帳を正本とします。

改訂4候補はStable Audioで生成した初回音の加工です。音色を保つため、再生成はしていません。崩壊は初回Aの大きな接触音から切り出して指数減衰させ、瓦礫は初回Bの再生速度・帯域を調整して小さな遅延成分を加えました。[prepare-round-2.py](prepare-round-2.py) と [round-2-optimization.json](round-2-optimization.json) に加工値・元音と出力のハッシュ・音量包絡を保持します。崩壊候補は機械検査で前半の短時間RMSが後半より大きいことを確認しますが、聴感の採用判断は人が行います。

JSONの書式第2版では、既存音の選定に加えて `additions` に追加したい音の場面・タイミング・希望音・メモを保存します。固定記号に切り替える前の発行済み2形式は、既存の保存内容を守るため明示的な対応で読み替えます。初回形式はA・B・Cをそのまま保持し、旧第2形式だけは崩壊・瓦礫のB→D／C→E、走行のA→C／B→A／C→Bと対応させます。同じ波形に対する確認状態とメモ・追加リクエストを保持します。未発行形式は受け付けません。この対応は旧データの移行完了後に削除可能で、削除時期は未定です。提出済みJSONは上記の履歴として保持します。
